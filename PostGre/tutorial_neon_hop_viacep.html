Integração de Dados com PostgreSQL (Neon), Apache Hop e API ViaCEP

Nesta atividade será desenvolvido um processo completo de Integração de Dados utilizando PostgreSQL hospedado no Neon, Apache Hop e a API pública ViaCEP. O objetivo é demonstrar um cenário real no qual uma empresa possui apenas o CEP cadastrado de seus clientes e necessita enriquecer seus dados consultando automaticamente uma API externa. Ao final do processo, os endereços serão gravados em uma tabela específica no banco de dados.

Fluxo da solução:

CLIENTE (PostgreSQL)
↓
Apache Hop
↓
API ViaCEP
↓
JSON
↓
ENDERECO (PostgreSQL)

Parte 1 - Preparação do Banco de Dados

CREATE TABLE cliente (
    id SERIAL PRIMARY KEY,
    nome VARCHAR(100),
    cep VARCHAR(8)
);

CREATE TABLE endereco (
    id SERIAL PRIMARY KEY,
    id_cliente INTEGER,
    cep VARCHAR(8),
    logradouro VARCHAR(200),
    bairro VARCHAR(100),
    cidade VARCHAR(100),
    uf CHAR(2)
);

CREATE TABLE log_erros (
    id SERIAL PRIMARY KEY,
    cep VARCHAR(8),
    motivo VARCHAR(200),
    data_erro TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

Inserção dos Dados

INSERT INTO cliente (nome, cep)
VALUES

('Maria','13010000'),
('Pedro','20040002'),
('Ana','13870000'),
('Cliente Inválido','99999999');

Conferência

SELECT *
FROM cliente;

Parte 2 - Construindo o Pipeline no Apache Hop

Estrutura final do pipeline: 

Table Input
      ↓
REST Client
      ↓
JSON Input
      ↓
Table Output

Passo 1 - Table Input

SELECT
    id,
    nome,
    cep
FROM cliente;

Criar uma conexão com o banco Neon e configurar um Table Input para ler os clientes.

Passo 2 - REST Client

Adicionar o transform REST Client e conectá-lo ao Table Input. 

URL Base
https://viacep.com.br/ws/

Criar os campos de saída response e status. O campo response armazenará o JSON retornado pela API.

Passo 3 - JSON Input

Configurar o JSON Input marcando: 

Source is a field
Field: response

Cadastrar os seguintes campos: 

cep_1        → cep
logradouro   → logradouro
bairro       → bairro
localidade   → localidade
uf           → uf
ibge         → ibge

Marcar também: 

Ignore missing path
Default path leaf to null

Passo 4 - Ajuste da Tabela Endereco

ALTER TABLE endereco
ALTER COLUMN cep TYPE varchar(9);

O ViaCEP retorna o CEP com hífen, exigindo nove caracteres.

Passo 5 - Table Output

Selecionar a conexão Neon e configurar: 

Target schema : public
Target table  : endereco

Marcar a opção: 

Specify database fields

Mapeamento dos campos: 

id_cliente   ← id
cep          ← cep_1
logradouro   ← logradouro
bairro       ← bairro
cidade       ← localidade
uf           ← uf

Não mapear o campo id da tabela endereco. Como a coluna foi criada com SERIAL, o PostgreSQL utiliza automaticamente: 

nextval('endereco_id_seq')

para gerar a chave primária.

Passo 6 - Executar o Pipeline

Executar o pipeline completo. O Apache Hop irá consultar a API ViaCEP, interpretar o JSON recebido e gravar os endereços na tabela endereco.

Conferência Final

SELECT *
FROM endereco;

Ao final da atividade os alunos terão construído um processo completo de ETL utilizando PostgreSQL, Neon, Apache Hop, API REST, JSON e carga automatizada de dados, reproduzindo um cenário comum encontrado em projetos reais de Integração de Dados.
